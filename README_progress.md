
🧱 階段 1：核心地基與多帳戶骨架（第一個月）

這個階段的目標是讓 App 的多帳戶、多語言和基礎路由跑通，不需要任何漂亮的美術。
• 🎨 外包美術任務：
	• 此階段不需要外包美術。請跟設計師談好第一階段的報價與風格即可。
• 🤖 GitHub AI 處理部分：
	• 初始化 Flutter 專案，設定 pubspec.yaml 依賴。
	• 撰寫 flutter_localizations 多語言架構與語系切換邏輯。
	• 使用本地儲存（SharedPreferences）建立多帳戶本地資料控制器。
	• 撰寫啟動邏輯：無帳戶 ➔ 建立帳戶；單一帳戶 ➔ 直達主頁；多帳戶 ➔ 選擇帳戶畫面。
• 🧪 你必須執行的測試項目（使用模擬器）：
	• 多語言測試： 手動切換手機系統語系至英文、繁中、簡中，確認 App 內的基礎介面文字能自動變更。
	• 初次啟動測試： 刪除 App 重新安裝，確認是否正確跳出「建立個人檔案（名字/生日/主語言）」畫面。
	• 單一帳戶自動登入測試： 建立一個帳戶後重啟 App，確認是否會自動跳過選擇帳戶畫面，直達（暫時是空白的）主畫面。
	• 多帳戶切換測試： 在設定頁新增第二個帳戶，重啟 App，確認是否正確顯示「帳戶選擇」畫面。

📝 階段 2：每日挑戰與核心題庫引擎（第二個月）

這個階段要讓思考關卡、每日挑戰、以及你設計的「扣分、保底、難度加成」算法完全動起來。
• 🎨 外包美術任務：
	• 請設計師交付 【C 組：試做型基礎貼紙（6張）】 與 【B 組：UI 元件（金幣、箭頭、D-Pad）】，用來當作關卡按鈕與過關獎勵的視覺。
• 🤖 GitHub AI 處理部分：
	• 讀取 questions_pool.json 題庫引擎，撰寫依年齡分級過濾題目的邏輯。
	• 撰寫「冒險傳送門」與雙語切換（主語言/自選英文）的出題 UI 介面。
	• 實現 核心獎勵經濟演算法：完美獎勵 15 枚、答錯一次扣 2 枚、保底 5 枚、難度加成、小數自動進位（ceil）。
	• 撰寫「每日挑戰」邏輯：每日限挑戰一次、答錯0分/答對3分、不計輸贏的累積參加計數器。
• 🧪 你必須執行的測試項目（先測試才能進入下一階段）：
	• 扣分與保底測試： 故意答錯 1 次（看是否得 13 幣）、故意答錯 10 次（確認是否有保底 5 幣）。
	• 難度加成與進位測試： 測試高難度關卡（如 3 歲或 4 歲），確認最終獲得的學習幣若有小數點，是否有自動進位（例如 16.5 幣變成 17 幣）。
	• 每日挑戰鎖定測試： 點進去每日挑戰並退出，確認當天是否無法再次進入。
	• 累積參加測試： 連續測試數天的每日挑戰（或請 AI 寫個外掛按鈕模擬跨天），確認不論答對答錯，累積參加次數都有正確增加。

🏝️ 階段 3：島嶼主地圖與貼紙拖拽系統（第三個月）

這個階段要把美術跟程式完美結合，讓孩子能把做題賺來的錢，拿去買貼紙佈置大屋。
• 🎨 外包美術任務：
	• 請設計師交付 【A 組：主地圖與場景（含大屋、4張未解鎖烏雲圖、大屋室內剖面圖）】。
	• （選做）若第一階段合作愉快，可請設計師開始大量產出其餘常規貼紙。
• 🤖 GitHub AI 處理部分：
	• 使用 Stack 元件建構主島嶼地圖，將烏雲圖層完美的疊在底圖上方。
	• 編寫金幣解鎖區域的邏輯，解鎖後烏雲圖層會消失，並儲存解鎖狀態。
	• 利用 Flutter 的 GestureDetector 和拖拽套件，編寫貼紙工具欄（含最近使用10個、分類分頁）。
	• 實現貼紙的雙指旋轉、垃圾桶刪除確認彈窗，以及一鍵解鎖的無限雙指縮放功能。
• 🧪 你必須執行的測試項目：
	• 貼紙拖拽流暢度測試： 測試同時拖拽 10-20 個貼紙在畫面上，確認畫面不會卡頓或崩潰。
	• 縮放與旋轉測試： 確認未開啟縮放功能時，貼紙只能旋轉；勾選縮放開關後，雙指能自由放大縮小。
	• 最近使用緩存測試： 點選不同的貼紙，確認「最近使用」欄位是否維持在最新的 10 個，且排序正確。
	• 金幣解鎖與儲存測試： 賺取足夠金幣後解鎖「奇妙海灘」，確認烏雲消失。關閉 App 重新打開，確認海灘依然是解鎖狀態。

💰 階段 4：RevenueCat 付費牆與權限控制（第四個月）

這個階段是應用的變現核心，要把免費版與訂閱版的「權限攔截」全部接上。
• 🎨 外包美術任務：
	• 請設計師設計一張漂亮的 「訂閱付費牆（Paywall）底圖」（要有 Piko 兔子、島嶼全開的吸引人視覺、以及訂閱按鈕按鍵）。
• 🤖 GitHub AI 處理部分：
	• 串接 purchases_flutter (RevenueCat) SDK。
	• 在所有核心功能（多帳戶建立、解鎖區域 1~4、冒險傳送門每日挑戰第二次、每日挑戰雙倍獎勵、累積限定貼紙領取）的前端，加上 SubscriptionManager.isPremium 的條件判斷。
	• 若為免費帳戶，點擊上述功能即彈出付費牆 UI。
• 🧪 你必須執行的測試項目（極度重要，關乎營收）：
	• 免費版限制測試： 使用免費用戶狀態，確認點擊「建立第二個帳戶」或「解鎖海灘」時，有正確跳出付費牆。
	• 每日挑戰正常獎勵測試： 免費用戶完成每日挑戰，確認拿到的只有正常獎勵（無雙倍），且累積限定貼紙會顯示鎖定狀態。
	• 沙盒購買測試（Sandbox Purchase）： 在 RevenueCat 測試環境下點擊訂閱，確認購買成功後，免費用戶能瞬間變成 VIP 狀態，且剛剛鎖定的特殊貼紙可以立即領取。
	• 恢復購買測試（Restore Purchase）： 測試「恢復購買」按鈕，確保家長更換新手機時能找回訂閱狀態。

🚀 階段 5：獨立遊戲加入與最終優化上架（第五個月）

最後的收尾階段，加入不影響每日挑戰的益智小遊戲，並打包上架。
• 🎨 外包美術任務：
	• 交付「找不同」的兩組對照圖片與相異點座標。
	• 交付「簡單迷宮」的地圖牆壁與主角圖案。
	• 交付 App Store / Google Play 商店所需要的宣傳圖。
• 🤖 GitHub AI 處理部分：
	• 在獨立傳送門中，建構「找不同」的點擊判定與難度過濾（2-3歲找3個；4-6歲找5個）。
	• 建構「2D 迷宮」與 D-Pad 方向鍵控制邏輯。
	• 全面檢查程式碼，清除測試用的 Dummy Data，準備打包。
• 🧪 你必須執行的測試項目：
	• 找不同座標測試： 實際點擊各個相異點，確認圈起的位置與實際圖片的相異處完全對齊，沒有產生偏移。
	• 迷宮碰撞測試： 控制主角去撞迷宮的牆壁，確認主角會被擋住，不會穿牆。
	• 雲端打包測試： 將程式碼提交至 GitHub，透過 GitHub Actions 或 Codemagic 打包出 iOS 的 .ipa 與 Android 的 .aab 檔案。
